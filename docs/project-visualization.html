Spring Boot 3

3.5.16 · Java 17

大楼物业管家：你只管放业务零件，接线、启动、水电、配送全部由它搞定。

  • 启动平台并自动装配所有组件，一行 main 就能跑起来
  • 对外提供 REST 接口，并托管内置前端页面
  • 用异步线程池执行评审任务，不卡住用户请求
  • 通过 SSE 把任务日志实时推送给浏览器
  • 从 application.yml 统一读取 MySQL、Redis、大模型配置

入口与配置

agent-server/.../JavaAgentPlatformApplication.java（@SpringBootApplication + main） agent-server/src/main/resources/application.yml

关键类与方法

ReviewController.createReview TaskService.createTask / runTask TaskLogBroker.broadcast / subscribe AsyncConfig.agentTaskExecutor GlobalExceptionHandler

LangChain4j

1.18.1

大模型万能插座：Java 程序不用研究 OpenAI 协议细节，把请求包装好发出去就有回答。

  • 评审增强：把规则问题拼成提示词，让 AI 补充人工点评
  • AI 对话：普通回答 + 流式回答，支持图片和历史消息
  • RAG：把历史报告变成向量，检索相似内容当参考

模型装配

agent-server/.../config/LlmConfig.java（OpenAiChatModel / OpenAiStreamingChatModel） LlmKeyCondition：没配 API Key 就不创建模型 Bean

关键类与方法

CodeReviewService.buildLlmPrompt / model.chat ChatService.chat / stream / buildLlmRequest ReviewRagService.indexDocument / search HashEmbeddingModel（本地免联网向量模型） MilvusRagConfig（可选向量库）

JavaParser

3.28.2

代码 CT 扫描仪：把源码解析成结构树，能精确指出第几行有个 if、第几行 catch 是空的。

  • 统计行数、类名、方法数、字段数、注释、TODO、圈复杂度
  • 规则体检：长方法、高复杂度、空 catch、System.out、Thread.sleep
  • 解析失败不中断评审，自动记一条 PARSE_ERROR

关键类与方法

agent-code-review/.../util/JavaSourceAnalyzer.java analyze（入口） collectMethodIssues（长方法 / 高复杂度） collectCatchIssues（空 catch / printStackTrace） collectCallIssues（System.out / Thread.sleep） ComplexityVisitor（圈复杂度统计） 模型：JavaFileSnapshot / CodeReviewIssue / Severity

JGit

7.7.1

Git 的 Java 遥控器：程序里直接打开仓库、读分支、算 diff，不用用户去终端敲命令。

  • 自动向上查找 .git 目录，读取当前分支和 HEAD 提交号
  • 对比 diffBase 与 HEAD，只审改动过的 Java 文件
  • 收集未跟踪文件；没给 diffBase 就全量扫描工作区

关键类与方法

agent-code-review/.../util/GitRepositoryScanner.java scan（入口） collectChangedJavaFiles（diff 改动文件） DiffFormatter.scan（对比两个提交） findGitDir（向上找 .git） listWorkingTreeJavaFiles（全量扫描） 模型：GitRepositoryInfo

MySQL

8.4

长期档案柜：重要数据写进硬盘，服务重启、断电都不会丢。

  • agent_task：任务状态、输入、输出、错误、时间戳
  • code_review_report：报告仓库、分支、统计、Markdown、AI 结论
  • code_review_issue：每一条问题的文件、行号、规则、级别
  • rag_document：RAG 历史文档
  • 连不上时自动降级为内存 + 文件，不影响主流程

配置

application.yml：datasource + jpa（ddl-auto: update） agent-server/pom.xml：mysql-connector-j

关键类与方法

TaskEntity / TaskRepository TaskService.toEntity / taskRepository.save ReviewReportEntity / ReviewIssueEntity ReviewRecordStore.persistToDatabase RagDocumentEntity / RagDocumentRepository

Redis

7

前台便签架：热点数据放在内存里，读写快，但断电会丢，适合放临时结果。

  • 缓存 Markdown 报告，key 形如 review:markdown:{reportId}
  • 缓存有效期 1 小时，避免每次都查数据库
  • 查询时先查缓存，未命中回源并回填
  • Redis 挂了自动降级，评审功能照常可用

关键类与方法

agent-code-review/.../cache/RedisReviewCache.java putMarkdown（写缓存，TTL 1 小时） getMarkdown（读缓存） ReviewController.getMarkdown（先查缓存再回填） application.yml：spring.data.redis + app.cache.redis-enabled

数据落点：每一份数据最后存在哪

不同数据放在不同地方，各有各的道理：要长期保存的进 MySQL，要读得快的进 Redis。

MySQL（长期档案柜）

agent_task 任务 ID、Agent ID、状态、输入、输出、错误、时间戳
code_review_report 仓库路径、分支、HEAD、文件数、问题数、Markdown 全文、AI 结论
code_review_issue 每条问题的文件、行号、规则、严重级别、消息
rag_document RAG 历史报告的原始内容，用于重建向量索引

Redis（临时便签架）

review:markdown:{reportId} 评审报告的 Markdown 全文缓存，TTL 1 小时
写入时机 GET /markdown 未命中时，从 MySQL / 内存读取后回填
降级策略 Redis 不可用时直接回源，不影响评审主流程

文件系统（本地备份）

data/reports/{reportId}.md 每份报告的 Markdown 也会落一份到磁盘，方便直接查看和导出
data/agent-platform-local 本地开发模式使用 H2 文件数据库，模拟 MySQL 语法

向量库（可选）

Milvus / 内存向量库 RAG 用的向量数据；默认内存库，配置 MILVUS_ENABLED=true 后切换到 Milvus
向量是什么 把报告文本变成一串数字，检索时用数字相似度找“以前的类似报告”
降级总结：没配 LLM_API_KEY，AI 增强自动跳过，规则评审照常；Redis 挂了，缓存自动失效，直接读库； MySQL 连不上，评审数据降级到内存和文件。这个项目的设计思路就是“缺了谁都能先跑起来”。

小抄与自测：10 秒看懂的术语，4 个自测题

Bean交给 Spring 创建和管理的 Java 对象
IoC 容器Spring 的“对象花名册”，负责存 Bean 和送货上门
依赖注入类只声明需要谁，Spring 自动把 Bean 塞进构造方法

JPA用 Java 对象直接操作数据库的“翻译官”

向量把文本变成数字串，用数字相似度找相关内容

自测题

先在心里答一遍，再点开看答案。

用户提交评审后，第一棒是谁？
Spring Boot 的 ReviewController 接收 POST /api/v1/reviews，然后交给 TaskService 创建任务、异步执行。
谁决定“只审改动的文件”？
JGit。GitRepositoryScanner 用 DiffFormatter 对比 diffBase 和 HEAD，只挑出变化过的 Java 文件。
Redis 挂了会怎样？
RedisReviewCache 捕获异常后返回空，系统直接读 MySQL / 内存，评审功能不受影响。
没配 LLM_API_KEY 会怎样？
LlmKeyCondition 不创建大模型 Bean，CodeReviewService 跳过 AI 增强，只输出规则分析结果。
